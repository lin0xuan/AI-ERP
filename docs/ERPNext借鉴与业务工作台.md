# ERPNext 借鉴与业务工作台

本次采用 ERPNext 的业务设计思路，在 Java / Vue 框架内独立实现。没有迁移 Frappe 运行时。此文记录实际交付边界，不代表已移植 ERPNext 全部功能。

## 已实现

- 主库存账本：行锁、数量守恒校验、事务内追加流水、移动平均成本、成本核定、最新变动冲销。历史成本未知时保留 NULL。非零且成本未知时，带成本的入库和调拨会被拒绝，必须先做成本核定；核定差额写入流水。库存清零时，最后一笔出库吸收尾差。
- 工作台单据：采购、入库、出库、盘点调整、成本核定、调拨。草稿 → 一级/二级审批 → 执行；制单人与审批人分离，规则在提交时固定。
- 采购执行生成现有 ERP 采购单；支持分批收货，按数量分摊附加费用，最后一批吸收尾差。工作台管理的采购禁止经旧采购状态/物流入口再次处理。
- 按用户、商户、店铺、仓库授权。范围受限账号的旧接口被阻止；聊天只注册受限查询工具，授权范围每次查询重新检查。
- 按补货点、人工维护的日需求、交期、包装倍数生成采购草稿。计入工作台未结束采购，重复请求不会重复生成。
- 单据、商品、供应商扩展字段：文本、数值、日期、选项、布尔；服务端校验、乐观版本检查、配置审计。
- Vue 工作台：库存流水、单据审批、补货、授权、字段配置、审计及当前页 CSV 导出。

## 部署

1. 先备份业务数据库。在测试环境验证后部署后端与 Vue 3 构建产物。
2. 后端默认幂等执行 `service/src/main/resources/db/erp-foundation.sql`，只新增 `ef_*` 表。若禁用自动建表，先手工执行此文件，并设置 `erp.foundation.initialize-schema=false`。
3. 执行 `docs/migrations/20261121_operations_menu.sql`，重新登录后在「业务工作台 → 库存采购与审批」进入。
4. 为角色配置 `erp:operations:read/write/post/approve/finance`，再由管理员配置具体数据范围。商户必须明确；店铺和仓库的 -1 表示该商户下全部。不要将通配管理员权限授予受限账号。
5. 使用至少两个不同账号分别制单、审批；二审需第三人。管理员也不能批准自己创建的单据。
6. 首次接管库存时记录期初数量；非零历史库存须经成本核定才有可靠价值。成本核定字段填写总成本，不是单价。

## 现有系统衔接与剩余工作

- 当前是主库存 `o_goods_inventory` 的数量/价值账本，不是全套批次、序列号、库位账本；工作台新收货尚未生成旧批次子账。上线前必须统一批次作业入口及迁移策略，不能当作全仓储替换直接使用。
- 原主库存增减/锁库服务已接账本，但旧调用没有稳定业务幂等键和完整来源单据；首次新建库存仍可能作为期初接管。尚需逐条迁移全部旧入库、订单发货、退货、盘点路径。
- 数据范围保护采用工作台入口及旧入口隔离，旧模块没有全部改成逐行权限查询。只有写入了商户/店铺/仓库范围的账号会被挡在旧接口外；只分配工作台菜单不会锁死其他页面。范围账号不能继续操作所有旧页面。
- 补货在途只统计工作台采购。其他入口采购尚未统一纳入；日需求不是自动预测。扩展必填字段存在时，自动补货制单可能被校验拒绝，需手工制单填写。
- 单据为单库存明细；跨币种、FIFO、销售毛利、会计总账、应收应付、多行单据、批次成本、自动重估、通用流程设计器、打印模板和全部旧页面字段渲染尚未实现。
- 冲销仅允许库存无后续变动的单据；否则使用新的业务调整单。历史流水不可直接删除或修改。
- 尚未部署到业务数据库，也未完成完整真实业务链路验收。部署脚本执行和上线验收仍待完成。

## 验证

新增 OperationsTest 17 项覆盖并发扣减、幂等、成本与冲销、未知成本拒收、尾差、越权、审批、规则快照、扩展字段、补货、调拨、采购分批收货和回滚。已在 H2 与独立 MySQL 8.4 测试库通过；采购桥接测试使用模拟采购服务，不能替代真实 MyBatis/完整业务表端到端验收。

全量测试报告：65 项，56 通过、9 项已有记忆集成测试跳过，0 失败。Vue 生产构建通过。合成数据浏览器夹具验证了制单、审批状态切换和补货展示；夹具不连接业务数据库或模型。
