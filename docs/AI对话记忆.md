# AI 对话与记忆

本实现连接现有 AI 助手、Spring AI 工具和 MySQL。短期上下文、长期记忆、工作记录分别存储；无需 Redis 向量模块或独立向量数据库。

## 使用

- 打开右下角 AI 助手，自动加载最近会话，也可用下拉框切换；刷新后可恢复历史。
- 说“请记住：我希望默认使用中文回答”立即触发长期记忆抽取。写入状态显示在输入框下方，模型不能代替系统确认写入成功。
- “记忆”面板查看长期事实、重要性、版本及工作记录；“旧版本”查看更新前的事实；“忘记”停止长期检索并删除该条旧版本。
- 新建或关闭对话发送结束事件。完成一轮回答也触发后台抽取；未正常结束的会话闲置 15 分钟后补做。后台每 60 秒扫描一次。
- 关闭聊天窗口中断浏览器接收，不会取消已经开始的服务端工具；服务端继续保存最终结果。此时再次发送可能提示正在处理，稍后恢复历史即可。
- 删除对话清理该对话原文、摘要和工作记录；已提取的长期事实需在记忆面板单独删除。

## 三层记忆与写入

| 层 | 内容 | 保存位置 |
| --- | --- | --- |
| 短期 | 最近三轮原文、本轮需求、临时约束、旧对话摘要与原文数字附件 | `ai_conversation_history`、`ai_memory_session` |
| 长期 | 用户直接陈述的偏好、事实、重要事件、明确要求保存的备注、超过 30 天的会话摘要 | `ai_memory_item` |
| 工作中间态 | 每轮 run id、步骤、工具名、参数、返回值、执行状态 | `ai_memory_work` |

长期抽取只接受用户原文中确实存在的连续引用，助手猜测不进入事实库。事件型记忆来自用户描述的重要事件；工具结果默认留在工作记录，不自动当作长期有效的业务事实。工具失败、服务重启中断同样留下状态。参数和结果中的常见凭据字段先脱敏。

抽取复用当前默认聊天模型。每次最多处理 10 条用户消息，其余保留待办标记；模型不可用时保留原文和待处理状态，稍后重试，不伪造摘要或声称已经写入。明确拒绝保存的消息跳过长期抽取。

## 冲突、压缩与遗忘

- 相同用户、类别、规范化主体属性键只有一条记录。模型先对照已有属性目录识别同义键；更新复用已有 id。有效值按来源消息 id 的新旧替换，同时增加版本和更新时间；旧值进入 `ai_memory_revision`。滞后任务不能覆盖较新的事实。
- 属性目录限制 40 条/18,000 字符，优先选择与当前消息相关的属性。模型归一化仍可能漏判同义表达，不能保证任意自然语言矛盾百分百识别。后台另做确定性的逐字/规范化重复归并，不会仅因向量相似就合并不同金额或不同事件。
- 最近三轮保留原文；之前的对话分批归并为“用户目标、已确认事实、待办步骤、未解决问题”摘要。摘要再更新时将上一层摘要作为输入，形成滚动压缩。
- 包含数字、金额、时间或“必须、禁止、不得、不要、预算、截止”等约束词的原句独立保存，并带角色和来源消息 id。模型摘要不会覆盖这些附件；原始对话也不删除。
- 这些原文约束默认最多 12,000 字留在提示里（`AI_MEMORY_ANCHOR_CHARS`）。超出的较旧原句原样写入长期库，键为原文哈希，不经过模型改写；提示里仍保留较新原句。检索时按重要性和相关性再取回。
- 闲置超过 30 天的会话进一步压成一条 `episode` 长期记录，明确标注“历史摘要，非用户逐字事实”。实时库存、价格仍需重新调用业务工具。
- 默认上下文字符预算 48,000，其中检索结果预算 6,000。预算是应用层字符控制，**不是模型的精确 token 计数**；应按部署模型窗口调小。若保留原文的必要约束和最近三轮仍无法装入，明确报错让用户缩小范围，不静默截断数字。
- 检索同时考虑相关性、1–10 的重要性、更新时间衰减、距上次使用的时间；命中后更新访问次数和时间。重要事实衰减较慢，但三年前的数据不会与昨天等权。候选集同时包含最近记录，以及重要性不低于 7 或用户明确要求记住的旧记录，避免只按更新时间截断后把旧的关键事实丢掉。
- 没有新用户消息可抽取时，空闲任务会结束本轮待办，避免每分钟重复调用模型。向量服务失败只跳过当条向量，关键词检索和遗忘仍继续。
- 普通低价值记忆 180 天未更新且未命中后退役；普通活跃记录默认软上限 500，超量按重要性和最近使用情况退役。明确要求记住或高重要性的记忆不会仅因时间久自动退役。退役/删除记录及旧版本在一年后清理；工具记录保留 30 天。明确长期保存的大量记录仍需用户主动整理。
- “忘记”还推进用户级历史抽取水位，防止旧对话被闲置任务重新提取；含遗忘水位之前消息的会话也不再转成长期 episode。代价是删除时尚未抽取的旧事实也不会补抽；后续新消息仍正常处理。原始对话依然保留，当前会话可能仍包含它，需要彻底清除时同时删除对话。

## 混合检索配置

未配置向量模型时使用关键词检索，界面明确显示降级状态。配置后使用关键词与向量余弦相似度混合排序，随后再做重要性与时间加权。后台每轮补建最多 10 条向量；模型/服务标识变化后不混用旧向量。向量服务失败时保留关键词检索。

```powershell
$env:AI_MEMORY_EMBEDDING_MODEL = '你的服务支持的向量模型名称'
$env:AI_MEMORY_EMBEDDING_ENDPOINT = 'https://你的服务地址/v1'
```

向量接口使用 `/v1/embeddings`，密钥复用页面中当前默认模型配置，不会读取或写入新的 API 密钥。向量端点必须接受这份凭据；仅支持聊天的模型服务不能直接用作向量服务。端点留空时使用默认聊天配置的服务地址。这里没有预填未知服务或替用户选择付费模型。

应用配置在 `erp-api/src/main/resources/application.yml` 的 `ai.memory`。可设置 `AI_MEMORY_CONTEXT_CHARS`；默认保留 3 轮、普通记录上限 500、闲置 15 分钟、低价值保留 180 天，均可通过 Spring 配置覆盖。

## 数据库与运行

默认 `AI_MEMORY_INITIALIZE_SCHEMA=true`，启动时以 `CREATE TABLE IF NOT EXISTS` 创建五张独立表，不改写业务表。首次 Docker 初始化也包含 `docs/migrations/20261119_ai_memory.sql`。已有数据卷不会自动执行 Docker init 脚本，应用初始化仍可创建记忆表。

如果运行账号没有建表权限，先用迁移账号执行上述 SQL，再设置 `AI_MEMORY_INITIALIZE_SCHEMA=false`。不要用全量业务 SQL 覆盖已有库。

同一用户的写操作使用 MySQL 租约串行化，避免两个标签页、后台整理或多实例同时更改上下文；后台续租，进程异常退出后租约最多 15 分钟过期。不同用户可并行。历史查询、删除、工作记录、版本查询均带服务端认证用户，模型不能选择用户 id。

## 验证

```powershell
mvn -pl erp-api -am test
npm --prefix vue3 run build
```

普通测试无需真实模型，HTTP 夹具覆盖真实 Spring AI 聊天客户端与向量请求协议。独立 MySQL 集成测试必须显式提供只指向本机 `memory_test` 库的 URL，否则跳过：

```powershell
docker run --name ai-erp-memory-test -d -e MYSQL_ALLOW_EMPTY_PASSWORD=yes -e MYSQL_DATABASE=memory_test -p 127.0.0.1:13367:3306 mysql:8.4
$env:AI_MEMORY_TEST_JDBC_URL='jdbc:mysql://127.0.0.1:13367/memory_test?allowPublicKeyRetrieval=true&useSSL=false&characterEncoding=utf8'
mvn -pl erp-api -am test
```

接口/逻辑覆盖：用户隔离、事实更新及版本、滞后写入、租约冲突、删除水位、工作状态持久化、低价值淘汰、数字原文保留、摘要失败不推进游标、拒绝模型编造引用、同义属性更新、向量独立召回、工具成功/失败。

界面夹具：启动 Vue 开发服务后访问 `/tests/memory-ui.html`，明确标记模拟数据，不调用业务库或真实模型。检查恢复历史、流式回答、记忆提示、长期记忆、旧版本、工作记录、删除与 Markdown 内容净化。

本轮已使用独立 MySQL 8.4 完成集成测试，并使用浏览器测试界面夹具。尚未对真实模型进行付费调用或对真实业务库做端到端验证；抽取质量及向量召回质量需要用部署环境的模型进一步评测。
